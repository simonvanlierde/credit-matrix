# Check CodeMeta attribution with citesync

The integration tests run the built Credit Matrix CLI on the same hand-checked roster as its CLI
tests. They merge its attribution fragment into fictional software metadata, then run citesync's
real `write` and `check` commands on disposable CFF and Zenodo files.

```sh
pnpm --filter credit-matrix build
pnpm exec vitest run integrations/codemeta/credit-matrix.test.ts
```

`pnpm verify` includes these checks. On the first run `uvx` installs a pinned citesync source
archive, so that run needs network access. The pinned commit supports CodeMeta's `id` and `type`
aliases and document-local identities; citesync 0.2.0 predates those fixes. It also vendors the
released codemeta-drift 0.4.0 mapping, with its release commit and both hashes in `MAPPING_SOURCE`.
The test pins the merged consumer revision.

The expected people are checked by hand, not generated by citesync. The tests verify names, missing
ORCIDs, author/non-author separation, unchanged CodeMeta roles, repeat-write idempotence, and
local identifiers surviving a CFF update of a CodeMeta target. They also check that an untyped
Zenodo contribution produces a reported gap and keeps the existing contributor list. Other writable
fields can still be updated in that case.

Credit Matrix supplies people and roles. Citesync owns format conversion and uses its existing
codemeta-drift mapping, so there is no second citation writer here. CFF has no general contributor
list or CRediT role field. Zenodo contributor types must be chosen separately; the successful
fixture starts with `DataManager` already selected. Keep the native roster JSON for scores and
contribution levels. This is a citation-file check, not a Zenodo deposit test.
